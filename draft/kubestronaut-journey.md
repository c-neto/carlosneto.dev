- KCNA (Kubernetes and Cloud Native Associate) – Conhecimento fundamental: se vc jah trabalha com kubrenetes, mesmo que nivel junior. vc tira ela com os olhos fechados. ela é pra quem tah começando. cai perguntas como o que é um pod? o que é um container. coisa bem basica para quem jah trabalha, mas nova pra quem esta estudaando. multiple escola.
- KCSA (Kubernetes and Cloud Security Associate) – Segurança básica de contêineres e clusters: Segue a mesma logica da KCNA, não é nada dificil, mas se voce trabalha com secops. Mesmo que vc seja um devops pleno ou ateh mesmo senior, voce nao pode substimar essa prova. cai muito conceito de Security, que meus colegas de SecOps sabem de cor e salteado, como o que é SBOM? qual argumento do trivy faz tal coisa? e etc. Ela soh vale a pena soh Se voce eh um secops aspirante ao mundo K8s ou quer tirar todas as certs e ser kubestronaut. é uma multipre escolha.
- CKAD (Certified Kubernetes Application Developer) – Desenvolvimento e implantação de aplicações: aki começa a ficar interessante. Essa certificacao contempla o conhecimento pleno de saber operar um cluster kubrenetes. voce precisa saber como escalar um deployment, como fazer rollback, como ver logs, analisar erros. A ideia aki eh usar kubernetes. O nome da prova pode enganar, voce nao precisa saber programar nada, no extremo maximo um script bash simples pra printar algo, bem simplao. Nao cobre criacao de Operator e etc. Conhecimento de pyhton, go, java sao totalmente inuteis para esse exame. A ideia do aki do Application Developer do nome da cert vem de uma pessoa que jah tem um cluster pronto rodando perfeitamente, e precisa fazer o deploy da sua aplicacao lah. das praticas, a mais simples.
- CKA (Certified Kubernetes Administrator) – Administração prática de clusters: aki as coisas começam a ficar mais denso. essa certficão cobre tudo que a CKAD tem, alem do principal dela: voce tem q ter o conhecimento sobre alguns pontos de provisionamento do cluster. ou seja, aki cai coisa como configurar o kubelet, diagnosticar problema de node que nao consegue entrar no cluster, ler logs do systemd, atualizar um cluster. 
- CKS (Certified Kubernetes Security Specialist) – Especialista em segurança de Kubernetes (exige o CKA prévio): essa é a prova que eu tenho mais ressalvas sobre o curriculo dela. pra mim, ela não é dificil, ela eh a que contempla mais assuntos e tools. nao eh nada muito profundo sobre os temas, mas sao muito temas. por exemplo, alem de assuntos de sec puramente de kubrentes como network policy, Role CLustreROle, aki voce traz perguntas de como usar ferramentas de sec para analisar assinaturas de imagens, verificar dependencias de imagens de containers, como rodar o docker sem acesso root. a minha ressalva esta que ela precisa da CKA como pre requsito, e pra mim não faz muito sentido. por exemplo na minha prova caiu uma questao para atualizar o cluster, o que isso tem a ver com security? enfim, pra mim eu acho que isso dificulta pessoas que querem ter ter uma trilha voltada de security. pra mim a pre requisito deveria ser. a KCSA.
- se voce é SecOps, minha sugestao é KCSA e depois CKA (infelizmente), e depois a CKS.
- se voce é um devops pleno ou ateh mesmo senior, e quer fazer soh uma, faça CKA.
- se voce é um devops juior, e quer conhecer com uma base solida, KCNA, depois CKAD, e CKA.
- se voce quer kubestronaut, faz KCNA, KCSA, CKAD, CKA, CKS.
